# 補充稿：00-overview.md

> **前置條件**：只有在決定收錄 [`pages/22-charts.mdx`](../22-charts.mdx) 時才套用本稿。
> 不收 charts 就整份跳過——目前的總覽頁在不收圖表的前提下是正確的。

## 為什麼要改

總覽頁的〈不收什麼〉現在寫著「**圖表元件**——這一版只收圖表色票 token，元件留待第二階段」。
新增 22-charts.mdx 之後這句話會直接自我矛盾。
文件互相打架比缺一頁更糟：讀者不知道該信哪一句，接著就會去問人，設計系統的自助性就沒了。

---

## 改動一：〈收錄範圍〉表格

在 `| 文件用 | Placeholder / Spotlight / MockScreenFrame |` 這一列**之前**插入：

```md
| 圖表 | BarChart、Pareto、StackedBar、TrendChart、Bullet、Scatter、Heatmap、LineChart、Legend |
```

放在「文件用」之前、「引導」之後，維持「產品元件在前、文件工具在後」的既有順序。

---

## 改動二：〈不收什麼〉第一項

**刪除**現有的圖表項目：

```md
- **圖表元件**——通用性夠，但需要自己一整套驗證（軸、圖例、互動、色盲檢查）。
  這一版只收[圖表色票 token](/foundations/color)，元件留待第二階段。
```

**替換為**（把原本「不收」的理由改寫成「收了，但邊界很窄」）：

```md
- **完整的圖表庫**——[圖表](/components/charts)只收「後台閱讀型」的八種零相依 SVG 圖，
  刻意不做縮放、刷選、圖內鑽取，資料點也只撐到百位數。
  需要分析型互動請直接用成熟圖表庫，不要改造這一組。
```

理由：〈不收什麼〉的價值在於劃線，不在於清單長度。
線從「不收圖表」移到「不收分析型圖表」，這一段仍然在做同一件事。

---

## 改動三：〈共同約定〉第 5 條後補一條（選用）

現有五條約定是給所有元件的。圖表多一條特有的：

```md
6. **分類色與狀態語意脫鉤**——圖表序列色只表達「這是哪一類」，
   好壞一律走 `success` / `warning` / `danger`。換整套圖表色票不會動到狀態語意。
```

這條也可以不加（22-charts.mdx 的〈色票〉一節已完整說明）。
若總覽頁希望維持「一眼看完所有跨元件約定」，就加；若希望總覽保持精簡，就不加。
**這是需要人工判斷的取捨，不要兩邊都做。**
