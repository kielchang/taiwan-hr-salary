# 附錄 B｜Excel 設計說明

> 本附錄供後續維護 Excel 工作簿（`excel/薪資計算系統_115年版.xlsx`）的人：說明它**為何這樣設計**（B1）、**如何構成**（B2）、**用了哪些試算表技術**（B3），以及**如何安全地調整**（B4）。儲存格層級的公式對照見 [附錄A](附錄A_Excel公式對照.md)，本附錄不重複羅列公式。

## B1. 設計理念

工作簿是 [README](../../README.md) 設計的**參考實作**：README 是規格，工作簿只是其中一種落地。維護時的判斷順序永遠是「規格說什麼 → Excel 怎麼實現」，不要反過來從儲存格推測規則。

README §2 的八條設計原則，落到試算表的具體決策如下：

| 設計原則 | Excel 落地決策 | 取捨說明 |
|---|---|---|
| P1/P2 規則與參數分離、單一來源 | 全部法定數值集中「參數設定」一張表，全簿以 `參數設定!$C$n` 絕對參照；嚴禁公式內寫死數字 | 試算表最自然的單一來源；犧牲：無變更紀錄（以檔案版本化補償） |
| P3 屬性驅動的工資項目 | 「薪資結構」以欄位承載八個工資項目，伙食津貼欄套用免稅上限屬性 | 新增項目＝插欄＋掛屬性，公式形狀不變 |
| P4 分流的眷屬模型 | 「眷屬名冊」獨立子表＋「依附健保」「報稅扶養」兩個是/否旗標欄，統計回寫主檔 | 絕不在員工主檔手動維護兩個人數 |
| P5 自動與人工的界線 | 系統建議值與人工結算值分離為兩格（four-eyes） | 見 B3 第 5 點 |
| P6 估算必須標示 | 估算欄輸出指引文字而非假數字 | 例：查表分支回傳「查115年扣繳稅額表」 |
| P7 可驗證性 | 檢核欄＋條件式格式即時紅標 | 見 B3 第 4、6 點 |
| P8 捨入策略明確化 | ROUND 出現的位置即捨入時點，是規格的一部分 | 見 B3 第 8 點 |

## B2. 工作簿架構

### 分層（16 張工作表）

| 層 | 工作表 | 性質 |
|---|---|---|
| 文件層 | 使用說明、欄位填寫指南、法規注意事項 | 唯讀說明 |
| 參數層 | 參數設定、勞保級距表、職保級距表、健保級距表、勞退級距表 | 年度維護 |
| 主檔層 | 員工清單、眷屬名冊、薪資結構 | 人事／核薪時維護 |
| 計算層 | 所得稅扣繳對照、薪資總表、獎金扣繳試算 | 自動計算＋每月變動輸入 |
| 輸出層 | 部門成本彙總、薪資條 | 自動彙總／列印 |

### 資料流

```mermaid
flowchart LR
    P["參數層<br/>參數設定＋4 張級距表"] --> M["主檔層<br/>員工清單・眷屬名冊・薪資結構"]
    M --> C["計算層<br/>所得稅扣繳對照・薪資總表・獎金扣繳試算"]
    P --> C
    C --> O["輸出層<br/>部門成本彙總・薪資條"]
```

### 逐列對齊架構（理解全簿的關鍵）

員工清單、薪資結構、所得稅扣繳對照、薪資總表採**同列同人**：第 n 列在每張表都是同一名員工。跨表參照因此不需查找函數（直接寫 `員工清單!J4`），代價是**任何一張表都禁止刪列與排序**，否則整簿錯位。唯一例外是眷屬名冊——它以 COUNTIFS 彙總、不依賴列對齊，可自由增刪列。

### 容量設計

員工 50 列（第 4–53 列）、眷屬 200 列（第 4–203 列），公式預先埋滿全部容量、以守門公式控制顯示（見 B3 第 1 點）。擴充容量的步驟見 B4。

## B3. 核心設計方法與技術

1. **守門公式＝紀錄生命週期管理** — 預埋列的每條公式外層包 `=IF(員工清單!A4="","",…)`：員編空白＝整列隱形。新增員工＝填入空白列；離職＝清空該列。效益：不需動態增刪列，與逐列對齊架構相容。
2. **級距查表＝VLOOKUP 模糊比對（TRUE）** — 四張級距表各附「下限」輔助欄並依下限**遞增排序**（這是 VLOOKUP TRUE 正確運作的前提，調整級距表時不可破壞），月薪資總額落入區間即回傳該級投保金額；超過最高上限由表尾最高級自然承接（觸頂）。
3. **一對多關聯＝COUNTIFS 模擬外鍵彙總** — 試算表沒有外鍵；眷屬名冊以「員編欄＋旗標欄」雙條件計數回寫主檔，得到健保眷屬數與扶養人數兩個獨立統計（P4）。
4. **參照完整性＝IFERROR＋VLOOKUP 自我標示** — 眷屬名冊查無員編時顯示「⚠查無此員編」並紅底；孤兒紀錄自我暴露而非靜默忽略（V2）。
5. **Four-eyes＝兩格分離** — 系統建議值放「所得稅扣繳對照」，實際結算值是薪資總表的獨立輸入格；人工轉填這個動作本身就是審核（README §7 控制點）。
6. **勾稽＝差異列恆存在** — 部門成本彙總每個分類區塊固定設「(未填寫/差異)」列＝全體合計−已分類合計；恆為 0 即正常，>0 即紅標（V3）。不是「出錯才出現」，而是永遠在場、永遠該是零。
7. **顏色語意＝低成本的權限控管** — 橘標題＝輸入欄、深藍標題＝公式欄（勿改）、黃底＝公司自訂假設（職保費率、年資基準日）。試算表沒有真正的權限控管，以視覺約定補位。
8. **捨入實作** — ROUND 只出現在法定金額的產生處（各保費、稅額、加班費、請假扣款），加總式一律不再 ROUND；唯一例外：健保自付「先捨單口、再乘口數」（README §5.6、§6）。

## B4. 維護與調整指引

### 日常維運

- **每月**：薪資總表 B1 改年月 → 填變動項（加班 E–I／其他加項 K／獎金 L／請假 N–O／累計獎金 T／其他扣款 W）→ 將所得稅扣繳對照之建議稅額人工轉填總表 V 欄 → 確認部門成本彙總差異列＝0 → 薪資條逐人輸出 PDF → 另存歸檔（工資清冊依法保存 5 年）。
- **每年 1 月**：依 [來源01](../sources/來源01_法定費率與基本參數_115年.md) 之年度檢查清單更新「參數設定」與四張級距表（⚠ 116 年勞就保合計費率升至 13%）；各參數的儲存格位置見附錄A §A1。
- **人員異動**：新進＝員工清單空白列＋薪資結構同列＋（如有）眷屬名冊；離職＝**清空該列、勿刪列**；眷屬名冊可直接刪列。

### 結構調整（變更設計時）

- **擴充員工容量**：50 列上限牽動十餘張表——預埋公式下拉、SUM 合計範圍、資料驗證與下拉清單來源需全部同步延伸，漏一張表即錯位或漏算。
- **新增工資項目**：在薪資結構插欄並掛上 P3 屬性（是否工資／是否應稅／免稅上限），確認「月薪資總額」的 SUM 範圍涵蓋新欄；禁止以項目「名稱」寫判斷邏輯（README P3 的法律理由）。
- **新增工作表**：凡逐人列示者，必須遵守逐列對齊（第 n 列＝同一人）且全列包守門式，否則破壞全簿一致性。

### 禁區

- 禁止刪列、禁止排序（眷屬名冊除外）。
- 勿覆寫深藍標題之公式格；發現公式被蓋掉請勿存檔，回復後再操作。

### 已知限制

1. **無稽核軌跡**：儲存格覆寫不留紀錄；正式環境建議檔案版本化＋存取權限控管。
2. **V4（46 小時加班上限）未實作**：技術上可用條件式格式達成，列為待辦。
3. **公式與輸入格同表共存**：誤改風險高於資料庫實作，僅靠顏色語意防護。
4. **與繳款單 ±1 元**：官方分擔金額表捨入時點不可考，以勞保局／健保署繳款單為對帳基準（README §6）。
