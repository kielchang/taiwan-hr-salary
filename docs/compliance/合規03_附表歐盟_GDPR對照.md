# 合規03 附表：歐盟——GDPR 對照

> 前提定位見 [合規00](./合規00_系統定位與適用邊界聲明.md)。對策代號同合規02。
> 條文引用以 GDPR（Regulation (EU) 2016/679）為準，屬對照定位用途。

## 1. 適用性判斷

台灣公司使用本系統，落入 GDPR 適用範圍的典型情境：(a) 在歐盟設有據點（establishment，Art.3(1)）並處理其員工資料；(b) 僱用居於歐盟的遠端員工。**若無上述情境，GDPR 不適用**；本附表仍以「採最高標準對齊」的立場完成對照，因為 GDPR 的控制要求是各法域中最完整的參照系。

角色定性：使用組織＝控制者（controller）；本系統為純本機工具、開發者不接觸任何資料，**不構成處理者（processor）**——這是純前端架構在 GDPR 下的真實優勢（無需 Art.28 DPA）。

## 3. 本系統特別議題

### 3.1 眷屬＝第三人資料主體

眷屬名冊（姓名、身分證、生日、健保依附、報稅扶養）的資料主體是**非員工的第三人**，其資料經員工之手間接蒐集（Art.14）。控制者義務：於取得後合理期間內（至遲一個月）向眷屬本人告知——實務上由「員工轉知」＋書面告知範本完成。範本01 需含眷屬版告知文。此議題在台灣個資法 §9 亦同構。

### 3.2 抹除權 vs 稽核鏈的張力

Art.17 要求抹除，內控要求稽核留痕。本系統的解法（ADR-041/042）：主檔刪除＋稽核殘留**假名化**（P1）——保留鏈完整性（selfHash 重算後以假名化內容重封或以 tombstone 註記），移除可識別內容。這是兩義務的平衡點，寫入範本03 DPIA 的緩解措施節。

## 5. 小結

GDPR 對照的淨結論：本系統「資料不出裝置」的架構讓它天然避開跨境傳輸（Chapter V）、處理者鏈（Art.28）等重負擔；代價是 Art.32 的技術措施全數落在本機層（P0 補加密與完整性）與組織層。適用 GDPR 的組織在完成 P0–P2 後，主要殘餘工作是文件化（ROPA、DPIA、告知文）與程序（72 小時通報）。
