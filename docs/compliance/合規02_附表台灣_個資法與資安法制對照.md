# 合規02 附表：台灣——個資法與資安法制對照

> 前提定位見 [合規00](./合規00_系統定位與適用邊界聲明.md)。差距對策代號：P0＝1.12.0、P1＝1.13.0、P2＝1.14.0（範本）、後端＝需 ADR-044 後端演進、組織＝使用組織的管理措施（系統外）、N/A＝不適用（附理由）。
> 法規版本基準：個人資料保護法（下稱個資法）及其施行細則、勞動基準法，以 2026-08 現行條文為準；主管機關已整合至個人資料保護委員會。條文引用為對照定位用，正式適用請以全國法規資料庫現行條文與主管機關函釋為準。

## 1. 適用性總說

使用本系統的民間企業 HR，其法律角色：

- **個資法**：非公務機關（§2⑧）。蒐集處理員工與眷屬個資的合法事由主要為 §19①二「與當事人有契約或類似契約之關係」（勞動契約）及履行法定義務（勞健保、扣繳）。
- **勞基法**：雇主，負工資清冊（§23）與出勤紀錄（§30）置備保存義務。
- **本系統的角色**：使用組織的**作業工具**。個資法上的責任主體是使用組織（雇主），不是軟體本身；本附表評估的是「工具是否讓使用組織有能力履行其義務」。

## 4. 資通安全管理法適用性說明

資通安全管理法的義務主體為**公務機關**與**特定非公務機關**（關鍵基礎設施提供者、公營事業、政府捐助之財團法人）。一般民間企業（本系統的預設使用者）**不直接適用**。但：

1. 上市上櫃公司經由證交所/櫃買中心的自律規範（§5 指引）與內控準則（§6）**間接承接**同等強度的要求；
2. 若使用組織屬關鍵基礎設施提供者（金融、能源、醫療等）之供應鏈，可能經由合約承接資安要求。

結論：本法對本系統為**參照框架**而非直接義務；對照重心放在 §5 與 §6。

## 5. TWSE/TPEx「上市上櫃公司資通安全管控指引」對照

指引（民國 110 年 12 月訂定）涵蓋治理、管理、技術、應變四個層面；以下摘選與本系統直接相關的控制類別對照（治理面如設置資安長、資安專責單位等純組織事項一律標「組織」，不逐條列）。完整條文以證交所最新公告為準。

| 控制類別 | 要求摘要 | 系統現況 | 差距 | 對策 |
|---|---|---|---|---|
| 資產與資料盤點 | 盤點資訊資產與核心資料 | 合規01 §4 個資盤點清冊 | 過去無 | P0（本文件）＋組織 |
| 存取控制與身分驗證 | 帳號權限管理、最小權限、特權帳號控管 | **無帳號體系**——純前端結構性缺口 | 上市櫃合規的最大缺口 | P0（密碼鎖＝單機最低限度）＋**後端**（OIDC/RBAC，ADR-044） |
| 資料加密 | 機敏資料傳輸與儲存加密 | 儲存明文（1.12.0 起可選 AES-256-GCM）；傳輸面無伺服器（HTTPS 由 GitHub Pages 提供） | 加密需使用者啟用 | P0＋組織（內規強制啟用密碼鎖） |

| 備份與復原 | 定期備份、異地保存、復原演練 | 手動 JSON 備份＋備份健康度提醒（1.11 在途）；無加密 | 備份未加密 | P0（備份加密）＋組織（異地保存、演練） |
| 委外與供應鏈管理 | 委外廠商資安要求 | 相依套件 13 個 runtime 依賴；部署於 GitHub Pages | 供應鏈風險由 CI 掃描部分承接 | P0（CI）＋組織（GitHub 服務條款評估） |

**結論**：存取控制、日誌集中兩類在本定位（單機工具）下無法滿足——這正是合規00 §6 升級門檻第 4 點的依據。上市櫃公司**不應**以本系統作為正式薪資系統，除非完成後端演進。

## 8. 小結與差距統計

- **P0 可解**：§27 安全維護的加密與稽核完整性（十一項中的 #9/#10）、告知（操作者層）、盤點與風險評估文件化。
- **P1 可解**：保存期限、當事人刪除權完整化、`note` 欄提示。
- **P2/組織**：事故應變、教育訓練、書面程序、匯出檔治理。
- **後端才能解**（上市櫃正式環境的硬門檻）：帳號體系與權限分級、職能分工的系統強制、日誌集中保存。
- 本附表確認的定位結論：**上市櫃公司可用本系統做薪資試算與底稿，不可作為正式薪資系統**；升級路徑見 ADR-044。
