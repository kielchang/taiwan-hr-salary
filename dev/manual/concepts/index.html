第2章 全域觀念

貫穿全站的核心規則：先懂這些，其他畫面的行為就都說得通。

📄️確認凍結與硬鎖定

每月結算的第二步是查核與確認頁。按下「確認本月結算」的那一刻，系統做兩件事：留存當月實際數字的快照（供年報累計與環比/同比），並把該月整月凍結——這就是「硬鎖定」：已確認月份的加班/獎金異動、薪資結構、眷屬、法定參數、調薪核定通通不能再改，相關畫面會直接提示你「先取消確認」。

📄️法定參數生效月版本化

每年 1 月政府公告新的最低工資、費率與級距。若直接就地改費率，先前已確認、已申報月份的數字會被回溯改寫——所以系統改用生效月版本：一旦有已確認月份，「系統設定 → 法定參數」的欄位會鎖上，並出現黃色提示卡「已有已確認月份 → 法定參數改用『新增生效版本』」。

📄️資料檢查 V1–V17

系統隨時自動跑一輪資料檢查，頂部狀態列顯示紅色「N 項待處理」（有錯誤）或綠色「資料正常」。查核頁的「系統檢查」卡會逐條列出：紅色（錯誤）＝會算錯錢或無法申報，必須處理；黃色（警告）＝建議人工確認。白話對照：

📄️破月計薪與員工生命週期

員工狀態有五種：在職／離職／留職停薪／停職／暫時離崗。月中到職、離職或留停時，系統按實際日數逐日加權計薪（破月）：例如月薪 45,000 元、6/16 到職，六月只發約半個月。留停/停職/暫離以「基本資料」員工檔案的區間紀錄管理——每一段有生效日、復職日（未填＝尚未復職）與給薪比例（不填＝採「系統設定 → 公司」的非在職給薪比例預設；停職半薪就是逐案填 50%）。同一人可以有多段紀錄（多次留停、多次復職），復職＝補填該段復職日即可，之後自動恢復全薪，不必改狀態。

📄️例行 vs 試算：什麼會寫回

全站數字分兩類，靠分頁上的「例行」（綠）與「試算」（藍）小徽章區分：例行＝實際結算的回顧（月報、年報、報表與申報）；試算＝薪酬分析裡的規劃試算沙盒（獎金/分紅試算、調薪試算），畫面上明白寫著「不會寫回實際薪資」——你可以放心調參數、比方案，不會影響月結。

📄️異動紀錄與回復

誰、何時、把什麼從多少改成多少——敏感異動都會留下稽核軌跡。先到「系統設定 → 資料與安全」填入操作者姓名，之後薪資/員工/代扣稅/月結/調薪核定/匯入/還原等變更都會記名。基本資料的每次情境異動（含必填的異動原因與前後值）集中在「基本資料 → 異動紀錄」分頁，可搜尋、可匯出 CSV。

📄️資料備份健康度

本系統是純前端應用：所有資料只存在這台電腦的瀏覽器裡，沒有雲端副本——清除瀏覽器資料、換電腦、重灌，資料就沒了。系統用三層提醒守著這件事：側邊欄底部常駐備份狀態（「今日已備份／上次備份 N 天前／尚未備份資料」，過久轉琥珀色，點擊直達備份分頁）、工作台在過久未備份時跳琥珀提醒卡、有未備份變更時關閉頁面前會跳瀏覽器確認。
